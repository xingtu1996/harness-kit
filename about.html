🧰 harness-kit

可回滚的角色化 Agent Harness 工作区生成器 · Apache-2.0 · 零遥测 · 零第三方依赖 · test 23/23

给强 harness，模型可以便宜 —— 把 AI 关进受控轨道的那套"项目 Harness"，按角色一键生成。

initpatchupgradedoctorsizeagent-prompt

为什么需要它

可控是分水岭

harness 不是工具收藏，是 AI 规模化使用的前提。模型会变、Agent 形态会变，"可控"不变 —— 分数逼近天花板，分水岭是"可不可控"。

强 harness → 不必强模型

把质量从"模型智力"迁移到"约束 + 工程 + 知识接入"，就能跑更便宜/更小/私有化模型而不塌质量（DS V4 Flash / GLM 5.3 Flash…）。

Agent 驱动 + 人可操作

全命令 --json 机器可读，agent 能读现状/差异/漂移给建议 —— 不只靠人脑记忆操作。

给老奶奶讲

给 AI 配的"工作台 + 使用手册 + 规矩"。模型再聪明，不懂你的规矩就乱来。harness 就像给新手员工的一本《岗位手册 + 操作规范 + 老员工笔记》。新项目十几秒搭好，老项目补规矩还能接上你的知识库 —— 省 token、少返工、质量稳、经验复利。

harness 接口长这样（真实实例）

.claude/                     ← Harness 根目录（AI 共享的"工作台"）
├── CLAUDE.md               ← 行为锚点：我是谁(角色)/怎么路由/铁律（AI 每次读的"名片+规矩"）
├── AGENTS.md               ← 给 AI 的导航索引（告诉它"你要的东西在哪个文件"）
├── DIRECTORY.md            ← 注册表：harness 里有什么、在哪（防资产漂移）
├── rules/                  ← 规则接口：治理护栏（宪法最优先；业务规则按需触发）
├── skills/                 ← 技能接口：SOP 打包（触发才加载，按需省 token）
├── workflows/              ← 流程接口：怎么一步步走
├── templates/              ← 模板元层：理念 / 方法 / 工程实践命名家族
├── memory/ + incidents/    ← 沉淀接口：知识 / 踩坑回流（复利飞轮落点）
└── hooks/                  ← 机械强制接口：规则是愿望、hook 是墙

一条命令

npm i -g harness-kit                 ***REMOVED*** 零第三方依赖
harness-kit init --role presale --json        ***REMOVED*** 售前：No-Spec-No-Code 门禁
harness-kit init --role code-delivery --json  ***REMOVED*** 开发交付：coding-gate
harness-kit init --role content --json        ***REMOVED*** 内容运营：content-gate + 知识接入点
harness-kit doctor --json                     ***REMOVED*** 受管 / 漂移 / 体积体检（agent 可读）
harness-kit agent-prompt --role presale       ***REMOVED*** 生成"复制给任意 Agent"的一段话

已有受管空间？`patch` 补缺 + 报漂移；preset 有新版走 `upgrade`（纯 lock 驱动 + 快照回滚，绝不覆盖你的手改）。

角色 preset · 克制 + 可定制

preset签名机制件（A9 立品实证）其余
B0 中性基座渐进披露 + 术语 + 模板元层一切 preset 的基座
presale 售前/FDENo-Spec-No-Code 门禁ready-for-agent 交接
code-delivery 开发交付coding-gate（Spec 先行 / 安全三条件 / 测试先行）{{stack}} 技术栈变量
content 内容运营content-gate（先查证 / 去 AI 味 / 标源）知识接入点（素材库/知识库）

每个角色 = B0 + 锚点 + ≤2 门禁件 —— 不堆全量 rules（省上下文税）。定制：改生成物占位永不覆写 → 自建 preset → 团队 preset 分发。

零门槛入门：一段话让任意 Agent 动手

请用 harness-kit 把当前目录搭成一个「{售前 / 开发交付 / 内容运营}」角色的受控 AI 工作台。读 README 安装 → harness-kit init --role {角色} --json 先预览确认 → harness-kit doctor --json 报告受管/体积/漂移。

复制给 Claude Code / 豆包 / Qoder / ChatGPT / WorkBuddy / TraeWork… 任何 Agent，它自己动手。

团队统一 · 规模化

从团队标准 preset 统一（路线图 v1+）：公司标准 + 角色层 + 个人手改层（kit 永不覆写）→ 收敛同基座、批量升级、跨项目 doctor。理念源自一线团队标准规约包 —— kit 把它从"人肉复制 zip + 搜 {{变量}}"变成可回滚的生成与治理。

安全 · 纯净 · 可信

  • 零遥测零埋点：不把你的数据外发；内网可 `--no-telemetry` 硬禁
  • 高敏分级：hook/脚本/设置类写入需 `--trust` 人审
  • 纯 lock 驱动：每受管文件内容 hash；你的手改 kit 永不覆盖，只报漂移
  • 快照回滚：写前留底 N 版，写坏能还原；dest 越界被拦截
  • 第三方扩展 opt-in + archive 拉取 + sha 锁定（不自动信远端新版本）

生态 · 关系自解释

harness-kit = 散仓资产的角色化编排生成器；xingtu-harness 是"一键装配全部"，harness-kit 是"按角色 × 平台生成专业规约 workspace"—— 互补同源，引用不复制。
