## 一、角色（当前待定）

当前为 **role-中性基座**：只装公共规矩 + 通用方法论 + 模板元层。角色化两种入口：

- `kit init --role <presale|code-delivery|content>`（新目录重建）
- `kit patch --role <presale|code-delivery|content>`（后续版本）

## 二、红线（最高优先级，违反即事故）

1. 禁止 `rm` / `rm -rf` 删文件 → 走安全删除（mv 回收站，可恢复）。
2. 批量/结构性改动前先打快照备份。
3. 禁止 `git add -A`：只精确定向 add。
4. 自包含：可复用产物不硬编码绝对路径，纯净环境可跑。
5. 决策留痕：关键决定写清依据与验证程度（BUL 依据链）。

## 三、术语（三行）

- **受管区** = harness-kit 生成的文件（`.claude/CLAUDE.md`、`.claude/rules/`、`.claude/templates/`、`AGENTS.md`），内容 hash 记于 `.harness-kit/lock`。
- **手改区** = 你在受管文件上的本地改动；kit v0.1 永不覆盖，检测到即报「漂移」。
- **漂移** = 磁盘文件 hash ≠ lock 记录 hash（受管文件被手改）；处置：保留手改，内容升级走 `kit upgrade`（M3+）。

## 四、通用思维方法论（C13 标准提示词族）

> 以下为可被 agent 直接调用的标准 prompt。可要求：请严格按 <N> 节方法执行。

### 4.1 第一性原理
把问题剥到不可再分的基本事实，再向上推演。禁止用类比、行业惯性或"别人都这样"作答。

### 4.2 对抗性审核
方案/对外产物必经多立场交叉审查：refuter（挑错）→ optimizer（改优）→ auditor（查依据与脱敏），裁决归人。

### 4.3 反机械执行
Intent over Compliance：不附和指令字面。先查事实、能思辨、必要时拦截；执行前用一句话说清你打算怎么做。

### 4.4 举一反三执行
复用先于重造：动手前先查本工作区是否已有可复用资产；不懂就问；同类问题带出解法（不是只答当前问）。
